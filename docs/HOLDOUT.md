# Holdout, сплиты и права на материалы

Сьют делится на три сплита, и только один из них публикуется текстом:

| Сплит | Кому виден | Что публикуется |
|---|---|---|
| `public-dev` | публично | prompt, workspace, dialogue, tools, system, assets, oracle, seeds |
| `audit` | внутренний поиск дефектов оценщика | метаданные, баллы и SHA-256 всех полей; текста и seeds нет |
| `closed-eval` | закрытая сравнительная оценка | то же, что `audit` |

Закрытым считается не только seed. Публичный генератор плюс опубликованный seed
восстанавливают fixture, поэтому закрытые seeds тоже не выгружаются: в stube
остаётся `holdout_seed_count`. Oracle закрытого задания публикуется только
хешем.

## Назначение

Назначение делает `dailybench holdout assign` и фиксирует его в манифесте:

```bash
.venv/bin/python -m dailybench holdout assign docs/holdout.json
.venv/bin/python -m dailybench holdout assign docs/holdout.json --closed-share 0.4 --audit-share 0.2
.venv/bin/python -m dailybench holdout assign docs/holdout.json --pin IF-6=closed-eval --pin R-1=public-dev
```

Сплит выводится из task ID: SHA-256 по `dailybench/holdout/1:<id>`, первые 8
байт — точка в `[0, 1)`. Поэтому одинаковый ID остаётся в своём сплите между
прогонами, а добавление задачи не сдвигает соседние. Доли по умолчанию —
`0.40` закрытых и `0.20` audit: это соответствует проектному объёму «шесть
dev-случаев и четыре закрытых на семейство». `--pin` переопределяет отдельные
ID (шаблон, который обязан остаться закрытым, или семейство, которому нужен
публичный пример), не меняя бакеты остальных.

## Манифест

`schema/holdout.schema.json` (`$defs/manifest`) задаёт формат: версия, профиль,
seed, объявленные доли, по каждому сплиту — отсортированные записи
`{"id", "hashes"}`, хеш состава каждого сплита и общий `digest`. В `hashes`
лежат SHA-256 полей `prompt`, `dialogue`, `workspace`, `tools`, `system`,
`assets`, `oracle`; `workspace` хешируется каноническим JSON, `prompt` — байтами.
Манифест не содержит текста.

Хеши нельзя пересчитать из экспорта: `prompt_sha256` закрытой задачи в экспорте
и в манифесте — один и тот же хеш исходного текста, а не хеш пустой строки.

## Гейт

`dailybench export --holdout docs/holdout.json` расширяет фильтр приватных
задач: `audit` и `closed-eval` выгружаются stubs с `"private": true`,
`"split": "<сплит>"` и хешами. `--include-closed` публикует закрытый текст
явно и снимает гейт. После построения документа `export` вызывает
`check_export`, который проверяет:

- у скрытого задания `prompt` равен `null`, а `workspace`, `dialogue`, `tools`,
  `system`, `assets`, `oracle` и `holdout_seeds` отсутствуют;
- поле `split` совпадает со сплитом манифеста;
- все хеши stuba равны манифесту;
- каждое задание документа присутствует в манифесте;
- у каждого `public-dev` задания есть prompt.

`dailybench holdout check docs/holdout.json` делает то же и дополнительно
сверяет манифест с только что собранным сьютом: неизвестные и недостающие ID,
изменившийся хеш любого поля, разошедшийся `digest`. Проверка читает профиль и
seed из общих флагов, поэтому манифест, снятый на другом профиле или seed,
падает, а не молча проходит.

Гейт стоит на пути `export`. Workspace публичного экспорта не содержит
закрытых входов; закрытый материал монтируется отдельно только на закрытом
прогоне. Каталог, в котором лежат `tasks` закрытого прогона, не публикуется.

## Независимый аудитор

Аудитору достаточно:

1. `git`-ревизии репозитория и манифеста;
2. профиля, seed и `digest` из манифеста;
3. воспроизведения сьюта `dailybench holdout check` на этой ревизии;
4. сверки `digest` с подписанным до прогона значением.

Получив stubs и хеши, аудитор убеждается, что опубликованный экспорт — те же
задания, которые считались закрытыми, и что их текст не предъявлялся. Хеши
поля не доказывают «отсутствия контаминации» сами по себе: обучение модели на
этом материале остаётся отдельным вопросом, который n-граммный фильтр не
закрывает.

## Ограничения

- `closed-eval` перестаёт быть нетронутым после того, как его ошибки
  просмотрены: следующий цикл использует его как development, а закрытым
  становится новый материал. Статус «holdout» не наследуется.
- Закрытые seeds защищают только при закрытом генераторе. Публичный генератор
  с опубликованным seed не создаёт секретного теста.
- Назначение по хешу — детерминированное, но не стратифицированное: доля по
  категориям колеблется вокруг объявленной. Выравнивать её без `--pin` нельзя,
  иначе просмотренные результаты начнут влиять на состав.
- Манифест покрывает профиль целиком. Экспорт с `--only` проходит только с
  манифестом, снятым на том же срезе, иначе `check` сообщает о недостающих ID.
