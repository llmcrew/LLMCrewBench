# Артефакты в git: что и зачем

Репозиторий хранит не только код. Здесь — что именно опубликовано, какие
файлы исключены из публикации и как проверить целостность.

## Опубликованные артефакты

| Путь | Что это | Почему в git |
|---|---|---|
| `suite/20261020/` | Сьют для новых запусков: 96 задач и манифесты | Фиксированная версия входных заданий |
| `runs/deepseek-v4.1-flash-unc-1017/` | Сохранённый прогон стенда 1017: `report.md`, `report.html`, `visual.html`, `scores.json`, `speed.json`, `config.json`, `sizing.json`, кадры и страницы витрины (`_showcase`), `_vendor` | Исторический результат и доказательные артефакты |
| `reports/comparison-deepseek-1017/` | Сохранённое сравнение старых запусков (95/100 и 100/100) с локальными runtime-библиотеками в `_vendor/` | Историческая публикация, не новый прогон |
| `reports/comparison-deepseek-1021/` | Сравнение запусков 1021 и 1017-1021, с локальными библиотеками и страницами витрины | Актуальная публикация сравнительных результатов |

## Сьют и происхождение результатов

`suite/20261020/suite.json` содержит 96 задач и имеет SHA-256
`0a9a4db6cfe3b8f35ee9eb33c20287d69c801a8b13378329f4db4cccf3eb0cf4`.
Сохранённый `runs/deepseek-v4.1-flash-unc-1017/suite.json` описывает другой,
68-задачный сьют с SHA-256
`3ea49b96cb8deff818707e7ae95f9825a4f0761e12c2f29550452cce48527f76`.

`reports/comparison-deepseek-1017/` — зафиксированное историческое сравнение:
его 95/100 и 100/100 нельзя выдавать за новые результаты на `suite/20261020`.
Новый отчёт `reports/comparison-deepseek-1021/` содержит два снимка прогонов,
оба с SHA-256 сьюта `12c5875f3cc3013bea13f7f46ff0e307f4e5bddea05f844dfea2c13305405d27`;
это тоже не SHA-256 `suite/20261020`. Числа и сами отчёты остаются неизменными:
для нового результата нужен отдельный запуск с явно указанным хешем сьюта.

## Исходный результат и технический ремонт

Исторические страницы модели, статусы и баллы не переписываются.
Вариант с изменённым кодом хранится отдельно и показывается с пометкой
«Технический ремонт · не исходный результат модели». Если изменено только
время ожидания, а SHA-256 HTML совпадает, подпись другая:
«Исходный код модели · расширенный запуск». Таймаут оценщика не выдаётся
за требование исходного задания или доказательство неспособности модели.
Запись в `video/src/data/result-notes.json` связывает модель и сцену с исходным
статусом, причиной, ожидаемым результатом, отдельным клипом, описанием запуска
или правки и SHA-256 исходника и варианта. Баллы по этим показам не пересчитываются.
Если исходной HTML-страницы нет, новую сцену вместо неё не создают.

Локальный комплект видео для сравнения 1021 содержит 98 основных клипов:
84 записи страниц и 14 чёрных плашек с отдельным статусом причины.
Отдельно в `video/public/repairs/clips/` сохранены пять технических вариантов
стенда 1021: L-4, L-18, L-19 и L-24 с увеличенным временем запуска и L-15
с изоляцией области имён. У L-15 восстановлен запуск, но результат остаётся
очень тёмным; графические недочёты не исправлялись.
Проверки полного декодирования, длительности, PTS и SHA-256 лежат в
[`video/public/recording-quality.json`](../video/public/recording-quality.json)
и [`video/public/repairs/recording-quality.json`](../video/public/repairs/recording-quality.json).
Это доказательства видеозаписи, не новые баллы бенчмарка.

## Что исключено и почему

| Путь | Причина |
|---|---|
| `runs/deepseek-v4.1-flash-unc-1017/tasks.json` | 98 МБ: полные транскрипты; восстанавливается из `transcripts/` и переигрывается |
| `runs/deepseek-v4.1-flash-unc-1017/transcripts/` | 98 МБ сырых JSON агента |
| `runs/deepseek-v4.1-flash-unc-1017/hardware.json` | Машинные параметры стенда (GPU неизвестен) |
| `runs/_chat`, `runs/_logs`, `runs/_showcase`, `runs/_vendor`, старые прогоны | Внутренние и воспроизводимые |
| `video/public/clips/`, `video/bin/` | Сгенерированные клипы (20 с, 120 fps, H.264 CRF16) и комплектный macOS ffmpeg: большие runtime-артефакты не хранятся в git |
| `video/archive/*.part-*` | Архив клипов частями: до 20.10 лежал в git, теперь только `RESTORE.md` и `SHA256` |
| `video/dailybench-video.zip`, `video/dailybench-video.tar.zst`, `video/dist/` | Тот же архив одним файлом (и его zstd-близнец): GitHub отклоняет >100 МБ |

## Склейка архива

Части приходят из `video/archive/` на машине записи; в клоне репозитория
рядом лежат только `RESTORE.md` и `SHA256`. Архив собирается заново, когда
меняется состав записи (например, после перезаписи клипов в 120 fps), — старые
части при этом заменяются целиком.

```bash
cd /tmp && rm -rf restore && mkdir restore && cd restore
cat <архив>/dailybench-video.zip.part-* > dailybench-video.zip
shasum -a 256 dailybench-video.zip   # сверить с SHA256
unzip -t dailybench-video.zip
```

Дальше — по `video/RENDER.md`.

## Проверка опубликованного прогона

```bash
cd runs/deepseek-v4.1-flash-unc-1017
jq '[.[].earned] | add' scores.json        # 181
jq 'length' scores.json                    # 68
which ffprobe && ffprobe -v error -show_entries format=duration speed.json 2>/dev/null
```

Баллы в `report.md`/`report.html` соответствуют `scores.json`; витрина —
`visual.html` (живые сцены требуют `python3 -m http.server` из каталога
`runs/`, как описано в README).
